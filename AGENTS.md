# AGENTS.md — Руководство по проекту для ИИ-агентов Antigravity

> **Название проекта**: «Поздравление Другу — Пазл Впечатлений» + «Ретро-Зал Игр»  
> **Тип проекта**: Fullstack SPA (React 19 + TypeScript + Express + Vite 8 + Tailwind CSS v4)  
> **Назначение**: Интерактивный мультимедийный сайт-поздравление с днем рождения с блоками-пазлами, визуальным редактором контента и встроенным залом ретро-игр.

---

## 1. Архитектура и суть проекта

Проект представляет собой двухстраничное интерактивное веб-приложение:
1. **Пазл-поздравление (`activePage: 'greeting'`)** — модульная лента из блоков-пазлов, каждый из которых раскрывает грань дружбы: персональное письмо, авто-тематика со звуком двигателя и басами, детальная статистика из игр (Мир Танков / Tanks Blitz / Steam), ачивки из реальной жизни и финальный супер-салют.
2. **Ретро-Зал Игр (`activePage: 'retro_arcade'`)** — раздел ламповых браузерных игр из детства/юности с возможностью играть вдвоем/втроем на одной клавиатуре (Tank Trouble 2, Superfighters Flash через WebAssembly эмулятор Ruffle).
3. **Визуальный In-Place Редактор (`EditorModal`)** — встроенная панель редактирования любых текстов, блоков, параметров тачки, ников и карточек прямо в браузере с автосохранением в `localStorage` и кнопкой экспорта `config.json` / TS-кода.

## 2. Стек технологий

* **Frontend**:
  * **React 19** (`react`, `react-dom`)
  * **TypeScript 5.7+ / 7.0**
  * **Vite 8** + `@vitejs/plugin-react`
  * **Tailwind CSS v4** (`@tailwindcss/vite`) — стилизация через утилитарные классы и CSS-переменные
  * **Lucide React** (`lucide-react`) — набор векторных иконок
  * **Motion** (`motion` / Framer Motion v12) — плавные анимации и переходы
  * **Canvas Confetti** (`canvas-confetti`) — салют при открытии печати и кульминации
  * **Web Audio API** — программный генератор басового сабвуфера (`audioBass.ts`) и процедурный звук выхлопа/двигателя (`carEngineAudio.ts`)
  * **Ruffle (Wasm)** — эмулятор Flash для запуска `.swf` игр в браузере

* **Backend / Серверная часть**:
  * **Node.js** + **Express 4.21+** (`server.ts`)
  * **tsx** — выполнение TypeScript на лету без предварительной компиляции
  * Сервер выполняет двойную роль:
    1. *Development*: Встраивает Vite как middleware (`app.use(vite.middlewares)`), обеспечивая единый порт `3000` для API и фронтенда.
    2. *Production*: Раздает скомпилированную статику из папки `dist/` и обрабатывает API-запросы.
  * Реализованные серверные API:
    * `/api/stats/tanki`: Парсинг и расчет WN8/рейтинга игрока из «Мир Танков» (Lesta).
    * `/api/stats/blitz`: Загрузка и кэширование энциклопедии техники Tanks Blitz (732 машины с CDN) + статистика игрока.
    * `/api/stats/steam`: Получение профиля, уровней, часов и библиотеки игр Steam.
    * `/api/steam-avatar`: CORS-прокси для аватарок Steam и Lesta.
    * `/api/retro-mirror/*` & `/api/local-ruffle/*`: Прокси и раздача локальных сборок игр Tank Trouble 2 и Superfighters Flash (с корректными Wasm MIME-типами и заголовками).
    * `/api/car-audio`: Эндпоинты для аудио-состояний.

## 4. Как работает управление данными и состоянием

1. **Источник правды по умолчанию**: `src/data/initialConfig.ts`.
   - Включает имя, дату, повод, массив блоков (`blocks`), параметры статистики танков/Steam, и массив ретро-игр (`retroGames`).
2. **Локальное переопределение (LocalStorage)**:
   - В `src/App.tsx` при старте состояние инициализируется из `localStorage.getItem('greeting_config_v1')`. Если ключ пуст — берется `INITIAL_GREETING_CONFIG`.
   - При сохранении через визуальный редактор (`EditorModal`) данные записываются в `localStorage`.
   - Кнопка «Сбросить к исходным» очищает `localStorage` и возвращает конфигурацию из `initialConfig.ts`.
3. **Добавление нового блока**:
   - Описать тип в `src/types/greeting.ts` (`GreetingBlockType`).
   - Создать компонент в `src/components/blocks/`.
   - Добавить ветку рендеринга в `src/components/BlockRenderer.tsx`.
   - Добавить форму редактирования в `src/components/EditorModal.tsx`.
   - Добавить дефолтный элемент в `src/data/initialConfig.ts`.

## 5. Инструкции по запуску и разработке

### Предварительные требования
* **Node.js** версии 18+ (рекомендуется 20 или 22) или **Bun**.
* Менеджер пакетов: `npm`, `pnpm` или `bun`.

### Установка зависимостей
```bash
npm install
# или
bun install
```

### Запуск для разработки и тестирования (Development)

**Вариант 1 (Основной и рекомендуемый — Fullstack сервер):**
```bash
npm run dev
```
* Запускает `tsx server.ts`.
* Поднимает Express-сервер с подключенным Vite middleware.
* Доступен по адресу: **`http://localhost:3000`** (или порт из переменной `PORT`).
* **Работают все функции**: прокси танков/Steam, Flash эмулятор Ruffle, зеркало Tank Trouble 2, аудио стрим и HMR фронтенда.

**Вариант 2 (Только статический фронтенд Vite — быстрый тест UI):**
```bash
npx vite
```
* Запускает чистый Vite dev-сервер (по умолчанию `http://localhost:5173`).
* Подходит для быстрой верстки и проверки UI. Внешние API запросы к `/api/...` будут падать без бэкенда, но моковые данные блоков из `initialConfig.ts` отображаются корректно.

### Проверка типов (Lint / Typecheck)
```bash
npm run lint
```
Выполняет `tsc --noEmit` для проверки строгой типизации TypeScript.

## 6. Сборка и запуск на продакшене (Production)

### Шаг 1. Сборка фронтенда
```bash
npm run build
```
Команда собирает оптимизированные статические файлы в директорию `dist/`.

### Шаг 2. Запуск в продакшене

#### Вариант А: Полнофункциональный Node.js продакшен (Рекомендуется)
Для работы игровых зеркал и кэширования танков запускается Express-сервер в production-режиме:
```bash
NODE_ENV=production npx tsx server.ts
# или через PM2 для фоновой работы:
pm2 start "npx tsx server.ts" --name "str-vanya-dr" --env NODE_ENV=production
```
Сервер автоматически обнаружит папку `dist/` и будет отдавать скомпилированный фронтенд вместе со всеми `/api/` роутами.

#### Вариант Б: Docker & Docker Compose (Рекомендуется для изолированного запуска)
Проект полностью настроен для запуска в Docker без необходимости ставить Node.js на хост:

* **Для тестирования и разработки (Dev с горячей перезагрузкой):**
  ```bash
  docker compose up
  ```
  Код монтируется с хоста, Vite HMR обновляет страницу в реальном времени на `http://localhost:3000`.

* **Для продакшена (Production):**
  ```bash
  docker compose --profile prod up -d prod
  ```
  Или через сборку стандартного Dockerfile:
  ```bash
  docker build --target prod -t vanya-dr-site .
  docker run -d -p 3000:3000 --name vanya-site vanya-dr-site
  ```

#### Вариант В: Чистый статический хостинг (Vercel / Netlify / GitHub Pages / Shared hosting)
Если нужен только статический сайт без своего VPS:
1. Запустить `npm run build`.
2. Загрузить содержимое папки `dist/` в `public_html` любого веб-сервера (Nginx/Apache/Beget/Timeweb) или подключить репозиторий к Vercel/Netlify.
3. *Примечание*: Основной контент, поздравления, письмо, салют, Web Audio басы и встроенный редактор работают автономно в браузере. Для локальных зеркал игр (`Tank Trouble 2`, `Superfighters`) без бэкенда при необходимости можно настроить прямые внешние URL в `initialConfig.ts`.

## 7. Важные нюансы и рекомендации для агентов

1. **Не ломать аудио-контекст**: В браузерах `AudioContext` требует жеста пользователя (клик / тап) перед воспроизведением звука. Все синтезаторы (`audioBass.ts`, `carEngineAudio.ts`) спроектированы с ленивой инициализацией при клике на соответствующие кнопки.
2. **Scroll Lock в играх**: В `RetroArcadePage.tsx` реализован механизм перехвата клавиш (`ArrowUp`, `ArrowDown`, `Space`), чтобы они не скроллили страницу во время игры на двоих/троих. Не удаляйте этот `useEffect`.
3. **CORS и внешние аватары**: Steam и Lesta блокируют прямые запросы аватарок с чужих доменов. Для их отображения используется эндпоинт `/api/steam-avatar?url=...`.
4. **Конфигурация стилей**: Используется Tailwind CSS v4. Конфигурация стилей находится в `src/index.css` с использованием `@theme` и директив CSS.
5. **Безопасность и секреты**: Если требуется вызов Gemini API, используйте переменную окружения `GEMINI_API_KEY` (см. `.env.example`). Не коммитьте реальные ключи в репозиторий.
